# 我们对论文 RAG 项目的理解

整理日期：2026-10-13（Asia/Shanghai）。依据固定上游 commit [424a0eb99edf841994f2a9a053912b489d2a94ff](https://github.com/jamwithai/production-agentic-rag-course/tree/424a0eb99edf841994f2a9a053912b489d2a94ff) 与 [源码证据表](./source-map.md)。本文件是认知汇总，未新增上游运行验证。

## 六个维度

| 维度 | 我们的理解 |
| --- | --- |
| 定位、能力与价值 | 课程与参考工程围绕 arXiv AI 论文实现采集、解析、检索、问答、追踪、缓存及 Agentic 流程；主要价值是学习完整工程链路并复用其结构。源码存在与运行通过分别记录。 |
| 原理与架构 | 建库：收集整理 → Docling 解析 → PostgreSQL 保存正文与元信息 → 切块 → Jina 向量化 → OpenSearch 索引。问答：问题 → BM25 和向量检索 → RRF 排名融合 → 问题与相关片段交给 Ollama → 回答与来源。RAG 为本次输入补资料，无需为这条链路重新训练模型。 |
| 使用场景 | 上游默认 AI 论文研究。农业可使用论文、手册和试验记录，保留作物、地区、土壤、气候与实验条件；技术资料保留型号、版本和权限；项目研究保留仓库、commit 和验证状态。这三类迁移需要适配。 |
| 使用路线 | 围绕明确主题准备一批可靠文档与 10 个真实问题；整理来源和期待找到的证据；先跑通普通 RAG 并核对引用，保存运行基线后再扩展。资料集合、知识库、问答接口与验证记录可作为后续应用基础。 |
| 可扩展方向 | 新资料入口和定期更新，中文、扫描件、表格与 OCR，本地向量模型和私有部署，权限、版本与领域筛选，Agentic 对比和质量评测，资料助手、专题报告和与项目 001 长文写作的衔接。均待后续实现与验证。 |
| 如何判断有用 | 抽查解析完整性、相关资料是否找对、引用是否支持结论、缺资料时是否说明，测量核查时间、耗时、成本，并验证资料更新、缓存失效和故障恢复。当前尚未运行上游，导读页没有接入真实资料库或模型。 |

Agentic 的源码结构为领域判断、检索、相关性检查、回答或改写重试，默认最多检索两次。参数、模型接入、来源和追踪链路仍需复现核对。Airflow 负责采集调度，Redis 缓存普通问答，Langfuse 追踪过程；FastAPI、Gradio、Telegram 是已有入口。

## 图的制作与来源

本图由本仓库依据以上文字直接绘制，尺寸 2400 × 3500；不是上游界面截图、真实问答结果或农业知识库成果。原版固定版本、静态源码结论、拟议适配与未验证事项在图内分别标识。

使用 [overview_figure.py](./overview_figure.py) 生成 PNG 与 SVG，文字和布局可继续编辑。PNG 用 Pillow 11.3.0 和 Windows Microsoft YaHei 字体渲染；SVG 保留文字和矢量节点，依赖阅读环境可用的中文字体。SVG 不包含脚本、外部资源或嵌入字体。网页有等价的可展开文字版、图的替代文本、原图链接与 PNG / SVG 下载入口。

复用图时，保留来源、固定版本、日期和“尚未运行上游”的验证状态。`assets/04-rag-understanding.png` 用于仓库索引，`web/assets/` 中的 PNG 和 SVG 用于静态网页发布，两份 PNG 内容相同。

本次曾调用内置 imagegen 两次制作同一信息图，均因网络请求失败而没有产物；最终图为直接绘制的可编辑信息图，未使用生成服务的输出或 CLI 回退。
