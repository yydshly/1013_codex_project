BaoCut：可编辑视频、人机协作与设计模块研究
研究版本：7aa049e82e1367da013b7aba80f0b79033fa04ad
整理日期：2026-10-14（Asia/Shanghai）

定位
BaoCut 是以可编辑视频为中心的 AI 创作工作台，提供本地 Runtime、视频引擎、智能体与可视化编辑器。视频是持续编辑的对象，成片、字幕和音频是它的导出结果。

核心理解
底层负责实际执行，模型理解目标并调用工具，人在 UI 中查看、试听、直接调整与撤销，再用对话继续优化。双方围绕当前项目接着修改，最终效果由人验收。

视频能力
语音转写与时间信息、按模型支持区分说话人、原文/译文/双语字幕、翻译与跨语言配音、人声分离、口播去停顿和重录、脚本与旁白编排、图片生成、HTML 动效帧烘焙、章节/摘要/标题/文章和短视频衍生。

执行原理
Node Runtime 承接客户端与工具请求，模型侧组织任务；计算由模型/媒体 Worker 和任务调度执行，视频修改由 Rust VideoEngine/VideoStore 校验、事务提交与持久化，并产生版本、回执和事件，界面再展示当前状态。

人机协作
人通过 UI、智能体通过工具接口进入共同的视频编辑入口，使用命令、事务、版本检查与撤销。用户可修改具体句子或镜头，再要求 AI 只改指定范围；可靠保留人工内容仍需真实端到端验证。

模型与接入
桌面、CLI、MCP 和 Web 连接同一个本地 Runtime；工具目录共用，但不同入口暴露范围不同。智能体引擎和本地/在线模型可按支持情况选择，模型提供理解与生成，视频引擎负责确定的编辑操作。

输入
视频、音频、图片、文稿或创作简报，加上语言、长度、风格、素材与修改范围要求；后续还可提供 UI 调整、时间段引用和设计稿/设计系统的位置标注。

输出
可编辑视频项目、文稿、译文、字幕层、音轨与动态图形，以及 MP4、SRT/WebVTT、音频和便携 .baocut 包；新增设计稿、设计系统及 HTML/PDF。便携包可续改，但不含原视频完整事务与撤销历史。

新增设计模块
固定提交 7aa049e8 接入设计画布与设计系统，并连接智能体指导、检查/素材工具、会话卡片、工作区和标注。画布保留画板与 HTML 结构；设计系统保存颜色、字体、间距、组件、素材和用法规范。

新增模块价值
设计作品可直接改文字和样式，也可对元素、区域或规范条目写批注，让 AI 针对位置继续修改；后续设计稿可以引用规范与组件。视频 UI 协作原本已有，设计模块有自己的文件与宿主桥接机制。

实际价值
将批量处理、结果查看、人工接手、明确反馈和局部修改连成连续流程，减少成果搬运与反馈定位的过程，保留可继续编辑的作品和视觉规范。是否提高质量、减少返工或节约总费用，需要实际任务对照。

对我们的意义
可用于探索把学习笔记和 GitHub 项目理解制作成解说作品；也能研究工具执行、可视化状态、修改范围、版本与回执、撤销和人工验收如何组织成可靠的 AI 创作系统。

使用场景
已有口播与教程整理、跨语言内容发布、从简报制作产品说明或知识讲解、内容衍生与短视频、视觉设计稿与品牌规范整理。素材、事实、译文、声音和最终效果仍需人工核对。

可扩展场景
可进一步组织项目研究解说、学习课程、多语言内容版本、长素材再利用、品牌一致的内容生产、CLI/MCP 批量制作、带引用的文稿知识库和其他可编辑产物的协作界面；网页逐项说明能力组合与实现前提。

扩展实现前提
补任务清单、素材和版本登记、脚本与模板、术语与音色配置、重试和回执记录、品牌参数映射与人工检查点。知识库另需切块检索和引用层；设计稿到视频时间线的自动转换还需单独适配。

评估方法
选固定真实素材与相同目标，对照人工流程和 AI 协作；检查局部修改范围、人工改动是否保留、撤销恢复、成片质量、事实和字幕准确性、总耗时、调用费用与返工成本。

来源与许可
研究固定 commit 7aa049e82e1367da013b7aba80f0b79033fa04ad；上游为 BaoCut Community License 1.0 的源码可用许可。编辑器有 Claude Design 相关前端重建移植来源，图标字体分发许可仍待确认，具体用途以 LICENSE 为准。

边界与验证
已核对固定版本项目与架构文档，原创网页、协作教学流程、下载和手机布局已有检查。网页不执行真实视频引擎或模型，未复现上游、未证明效果和成本优势，也未证明设计稿自动进入视频时间线；公开部署另有验证记录。

八种可扩展场景（研究建议，尚未实现）
1. GitHub 项目研究解说
目标：把本仓库的研究说明、架构图和结论整理成可反复修改的短讲。
能力组合：研究文稿 → 脚本与旁白 → 图示/镜头/动效 → 字幕与人工修订。
实现前提：补脚本规划、图示与画面布局、事实和来源核对；设计稿进入视频时间线需要单独转换。

2. 学习笔记与教学课程
目标：把录音、口播或自己的学习笔记转成教程，保留字幕和时间线以便复习与修改。
能力组合：转写、章节整理、字幕、口播剪辑、知识讲解模板。
实现前提：补课程目标、知识顺序、素材清单和人工审阅；模型生成的解释不能代替事实核对。

3. 多语言内容版本
目标：同一作品制作多个语言版本，逐句调整译文、声音和字幕。
能力组合：翻译、双语字幕、人声分离、逐句语音合成与时间线铺轨。
实现前提：补术语表、语言/音色配置、每版进度与版本登记，逐句试听并核对含义和节奏。

4. 长素材与内容再利用
目标：从长口播、访谈或课程中整理章节、文章、标题和候选短视频。
能力组合：带时间文稿、章节与摘要、片段剪辑和衍生内容。
实现前提：保留源片段与时间戳，检查上下文是否完整；补候选列表、去重规则与成片验收。

5. 品牌一致的内容生产
目标：让海报、网页原型、封面以及配套视频采用一致的视觉规则。
能力组合：设计系统的颜色/字体/组件/素材，设计画布和原有视频模板。
实现前提：设计系统可供设计稿引用；视频字幕、字卡和动效的参数映射仍需适配，不能假定自动同步。

6. 批量制作与任务编排
目标：在素材目录和任务清单上重复执行固定流程，减少重复手工发起。
能力组合：CLI/MCP 工具入口、转写/字幕/导出、任务状态和变更回执。
实现前提：补批次清单、失败重试、资源与预算控制、版本记录及人工检查点；不同工具入口范围要逐项核对。

7. 带引用的文稿知识库
目标：把带时间的课程或访谈文稿用于检索问答，回答能回到原视频核对。
能力组合：BaoCut 的转写与时间信息 + 自建检索与问答系统。
实现前提：另建文稿导入、清洗、切块、索引、检索和时间戳引用；本研究未实现真实 RAG 接口。

8. 可编辑产物的人机协作应用
目标：借鉴“工具执行 + 可视化接手 + 位置反馈”的方式，扩展到其他创作工作台。
能力组合：编辑入口、当前状态、版本/回执、撤销、预览和人工验收。
实现前提：为目标产物设计自己的命令或文件协议、范围控制与同步机制；先验证小任务，再扩展自动化。
