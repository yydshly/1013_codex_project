## 我们的核心理解

BaoCut 将底层视频能力、智能体和可视化编辑器连接起来。人通过 UI 预览、试听、调整镜头与字幕，也可以提出自然语言要求；智能体理解目标后通过工具调用执行修改。双方继续修改当前项目。

三类职责需要分清：

| 角色 | 工作 | 输出与下一步 |
| --- | --- | --- |
| 人与 UI | 查看、试听、直接编辑、撤销、决定是否接受 | 当前人工修改与下一轮要求 |
| 模型与智能体 | 理解目标、组织处理、调用工具、修改指定范围 | 编辑结果与变更回执 |
| 底层与项目 | 执行剪辑、字幕、音轨、渲染和保存 | 可编辑视频及按需导出成果 |

视频部分，人和 AI 通过同一套命令入口、事务与撤销机制提交修改。AI 主要调用工具接口，不需要通过模拟鼠标点击剪辑；可视化 UI 给人查看和接手的入口。这里的“共享状态”指围绕当前项目继续修改，不代表所有真实模型都已证明能可靠保留每项人工调整。

## 源库原有能力

项目 README 描述的原有能力包括：

- 转写已有音视频，生成时间信息，按模型支持区分说话人。
- 原文、翻译或双语字幕；保存自己的字幕样式。
- 翻译、人声分离、逐句语音合成、跨语言配音并放入音轨。
- 去掉口头语、长停顿、重录片段等口播剪辑；保留原始媒体。
- 根据文稿生成章节、摘要、标题与短视频；按简报制作视频、图片及代码动效。
- 导出 MP4、字幕、文稿、音频和可继续编辑的便携 `.baocut` 包。

桌面、CLI、MCP 与 Web 连接同一个本地 Runtime。智能体引擎和模型供应方可以按支持情况选择。不能把“接口支持”当作每个后端和模型都完成了端到端验证；上游 README 已列出不同验证范围。

## 执行原理：模型规划与引擎执行分工

依据固定版本架构文档，Node Runtime 承接客户端与工具业务请求，Rust VideoEngine/VideoStore 拥有视频事务与持久化的权威。界面展示视频的投影，智能体根据当前上下文组织工具操作；两者不会各自维护一套独立的视频真相。

1. 获取当前视频、素材、文稿或设计文件，并把用户目标与选定范围作为本轮上下文。
2. 模型判断要执行的操作，智能体调用公开工具。模型生成的文本本身不是已经执行的编辑结果。
3. 转写、配音、图像等计算由任务调度和模型/媒体 Worker 执行。计算产物与“应用到视频”的动作分开记录；视频编辑要经过校验、版本检查、事务提交和持久化。
4. 返回回执与状态/视频事件，界面显示当前工作稿。人查看或试听后，可以直接改、撤销，或明确范围再让智能体修改。

CLI/MCP 共享工具目录与结果语义，但暴露范围不同；某些设计工具只用于会话中的智能体。长任务返回任务标识并需要等待终态，任务产生结果不等于已经应用或已经导出成片。局部编辑有时仍需重新渲染相关合成，缓存按实际依赖失效。

这是一种适合研究的分工：模型负责理解、规划和生成，确定的状态修改由编辑系统执行，人通过 UI 接手并验收。可靠保留人工内容与处理失败的实际效果，仍需端到端复现。

## 输入、输出与适用场景

输入包括视频、音频、图片、文稿或创作简报，以及目标、样式、修改范围、人工调整和设计模块的位置标注。输出包括可编辑视频、成片、字幕、音频、文稿与便携项目，以及新增设计稿、设计系统和 HTML/PDF。桌面 UI、CLI、MCP、Web 连接同一个本地 Runtime。

根据上述能力，我们认为可以尝试口播/教程整理、跨语言内容发布、产品或 GitHub 项目解说，以及配套视觉设计和品牌资料整理。对本研究仓库的具体价值是探索视频化笔记与项目展示，并学习 UI 接手、工具执行、范围控制、反馈定位和状态共享的方法；这些场景适配与收益判断尚未通过真实上游任务验证。

这次新增的是设计类作品与其集成。视频时间线、可视化编辑和视频人机协作在这次提交之前已有。设计模块有自己的文件布局、运行时与宿主桥接，不能将视频事务机制直接套到每项设计操作上。

作者说明设计画布来自 Claude Design 类型的 TypeScript 重建，设计系统来自原 Design System 类型的重建，再移植适配 BaoCut。应区分编辑器来源与本次宿主适配、工具、会话集成的贡献。相关说明仍列出重建残余风险和图标字体分发许可待确认事项。

设计稿指导明确把视频字卡和动效交给原有模块。本次提交未证明设计稿能自动进入视频时间线，也没有证明网页原型可直接作为完整业务应用上线。

## 协作案例与价值判断

网页示例依次演示：提出“一分钟产品口播”的目标 → AI 示例生成初稿 → 人在 UI 调整镜头与第二句字幕 → AI 示例只改第三句 → 人检查交付。用户可以输入自己的第二句，下一轮示例保留它；也可以撤销或重置。

这个演示仅说明目标工作方式，不证明真实上游执行结果。其价值判断是：

1. 批量处理交给智能体，人的直接调整能成为下一轮起点。
2. 用字幕句子、镜头或设计元素定位反馈，使修改范围更明确。
3. 保存时间线、结构化设计稿与视觉规范，方便后续修改和复用。
4. 最值得研究的是执行工具、UI 接手、状态共享、范围控制和撤销如何配合。

尚未证明返工时间、成片质量、任务成功率或成本优势。进一步验证应选同一真实任务，记录人工调整能否保留、局部修改影响范围、撤销结果、耗时、调用成本与最终人工验收。

## 八种可扩展场景与实现前提

以下是依据库的能力提出的研究与适配方向，不是默认已实现的新服务。

### 1. GitHub 项目研究解说

把本仓库的研究说明、架构图和结论整理成可反复修改的短讲。

- 能力组合：研究文稿 → 脚本与旁白 → 图示/镜头/动效 → 字幕与人工修订。
- 实现前提：补脚本规划、图示与画面布局、事实和来源核对；设计稿进入视频时间线需要单独转换。

### 2. 学习笔记与教学课程

把录音、口播或自己的学习笔记转成教程，保留字幕和时间线以便复习与修改。

- 能力组合：转写、章节整理、字幕、口播剪辑、知识讲解模板。
- 实现前提：补课程目标、知识顺序、素材清单和人工审阅；模型生成的解释不能代替事实核对。

### 3. 多语言内容版本

同一作品制作多个语言版本，逐句调整译文、声音和字幕。

- 能力组合：翻译、双语字幕、人声分离、逐句语音合成与时间线铺轨。
- 实现前提：补术语表、语言/音色配置、每版进度与版本登记，逐句试听并核对含义和节奏。

### 4. 长素材与内容再利用

从长口播、访谈或课程中整理章节、文章、标题和候选短视频。

- 能力组合：带时间文稿、章节与摘要、片段剪辑和衍生内容。
- 实现前提：保留源片段与时间戳，检查上下文是否完整；补候选列表、去重规则与成片验收。

### 5. 品牌一致的内容生产

让海报、网页原型、封面以及配套视频采用一致的视觉规则。

- 能力组合：设计系统的颜色/字体/组件/素材，设计画布和原有视频模板。
- 实现前提：设计系统可供设计稿引用；视频字幕、字卡和动效的参数映射仍需适配，不能假定自动同步。

### 6. 批量制作与任务编排

在素材目录和任务清单上重复执行固定流程，减少重复手工发起。

- 能力组合：CLI/MCP 工具入口、转写/字幕/导出、任务状态和变更回执。
- 实现前提：补批次清单、失败重试、资源与预算控制、版本记录及人工检查点；不同工具入口范围要逐项核对。

### 7. 带引用的文稿知识库

把带时间的课程或访谈文稿用于检索问答，回答能回到原视频核对。

- 能力组合：BaoCut 的转写与时间信息 + 自建检索与问答系统。
- 实现前提：另建文稿导入、清洗、切块、索引、检索和时间戳引用；本研究未实现真实 RAG 接口。

### 8. 可编辑产物的人机协作应用

借鉴“工具执行 + 可视化接手 + 位置反馈”的方式，扩展到其他创作工作台。

- 能力组合：编辑入口、当前状态、版本/回执、撤销、预览和人工验收。
- 实现前提：为目标产物设计自己的命令或文件协议、范围控制与同步机制；先验证小任务，再扩展自动化。
