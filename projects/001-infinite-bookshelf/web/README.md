# Infinite Bookshelf 中文理解与效果演示

**页面最上方明确说明：核心只是用代码组织多次模型请求，控制写书流程。** 原版输入主题，可补充读者、目标、范围和风格要求，高级模式还可加入笔记或 TXT 资料；模型生成目录、书名与分节正文，代码控制先后顺序、循环和汇总，最后展示并导出待人工编辑的 TXT/PDF 初稿。它没有新增模型能力，也没有自动保证全书质量。本研究演示的导出为 Markdown、TXT 与浏览器打印 PDF，和上游自动 PDF 转换分别说明。

这是一份独立编写的研究演示，汇总能力、原理、输入输出、实际效果、应用价值和局限。写作方法与手动让模型“先出大纲，再写细节”相同，价值主要是减少重复请求与整理，并把流程复用于不同主题或自有模型。较独立的教程和培训材料适合起草，复杂小说需要前文状态管理与人工审核；偶尔写作时额外价值有限，频繁生成同类长文时才更可能节省操作成本。网页以一图总览、固定源码证据、完整样稿与分步回放说明这些判断；它不是上游 Streamlit 界面的原样复现，也没有用样稿回放证明质量优于直接使用同一模型。

**默认展示「本次对话 GPT 生成样稿 · 流程回放 · 未通过项目 API 调用」。** 样稿来自本次对话，并非占位段落。其三节正文、教学案例和练习可直接阅读、下载；回放只是逐步展示保存好的结果，不能用来评估原项目或模型 API 的生成性能。

## 页面内容与交互

本轮网页扩展采用以下阅读顺序，让最重要的原理直接可见，再展开细节：

| 页面区域 | 锚点 | 说明 |
| --- | --- | --- |
| 一图总览 | `#understanding-overview` | 顶部原理后展示中文信息图，覆盖输入、执行、输出、能力、GPT 比较、价值、局限和两个例子；可收起、打开原图、下载 PNG |
| 顶部原理与职责 | `#principle` | 多次请求的核心；代码、提示词、模型、页面与导出分别做什么；不等于 Skill 或额外写作能力 |
| 提示词与执行控制 | `#prompts` | 目录、书名、正文三类提示词；目录 → 书名 → 解析目录 → 顺序扩写 → 汇总；软性要求与程序控制的边界 |
| 输入与输出 | `#input-output` | 主题是最低输入，读者、目的、范围、风格、资料能改善适配；输出是可修改初稿 |
| 样稿工作台 | `#workbench` | 完整摄影、电商样稿，分步回放、阅读导航与导出，以及模型 API 入口 |
| 与直接 ChatGPT 对比 | `#gpt-comparison` | 内容仍由模型生成，主要增益是自动执行与汇总；原版缺少前文上下文和编辑闭环 |
| 场景与具体例子 | `#scenarios` | 摄影教程为什么可以拆节；《水浒传》式群像小说需要原版没有实现的全书状态管理 |
| 部署与模型替换判断 | `#deployment` | 偶尔写作额外价值有限，重复任务与软件接入有复用意义；模型可换，但上游服务耦合要处理 |
| 来源与验证边界 | `#evidence` | 原版源码、作者历史样本、对话生成样稿、本地适配版与伪服务验证分别记录 |

提示词说明依据固定版本源码，不把“全面、不重复、准确、300 页以上”等要求当作已保证结果。原版正文只接收本节标题、描述和附加要求；我们的 API 适配版另外传完整目录和此前各节开头 600 字符的摘录。这一补充尚未做真实质量对比。

保留的交互能力包括：

- 样稿选择器提供「电商运营入门」和「手机摄影入门」。默认电商样稿贯穿一家虚构的保温杯店铺；摄影样稿提供面向零基础读者的手机拍摄学习材料。两份样稿均由本次对话 GPT 生成并保存。
- 打开 [摄影样稿](http://127.0.0.1:8765/?sample=photography) 可直接阅读手机摄影示例；无 `sample` 参数时仍默认电商。选择器会同步主题、要求、书名、目录、正文和来源，回放、恢复及下载均使用所选样稿。回放或真实模型请求期间禁用选择器，模型 API 模式隐藏选择器。
- 「回放写作流程」依次显示目录、书名、三节正文和汇总阶段；可以停止回放、重新开始、恢复完整样稿。
- 目录按钮定位到对应正文；正文支持基础 Markdown 标题、段落、列表、代码块、引用和表格。
- 下载 Markdown、TXT；使用浏览器「打印 / 存为 PDF」保存完整正文。没有复用上游的自动 PDF 转换库，打印排版由浏览器完成。
- 「接入模型 API」检查本地配套服务配置。配置有效后可编辑主题和要求，按阶段接收真实模型结果；服务不可用时保留样稿功能并显示原因。
- 实验记录分别展示对话样稿来源或模型 API 的实际请求统计。API 未报告用量时显示「未报告」；模型返回截断时在正文与下载文件标记需要补写。生成时间按北京时间显示。

## 技术栈与依赖

原生 HTML、CSS、JavaScript，无 npm 依赖，无构建工具，无外部字体、图标或运行时资源。样稿分别从相对路径 `./data/gpt-demo-book.json`、`./data/gpt-photography-book.json` 读取。样稿与界面文字使用文本节点渲染，模型正文不插入 `innerHTML`；这是基础 Markdown 解析，不提供 HTML 执行能力。

需要通过 HTTP 服务打开；直接双击 `index.html` 时，浏览器可能阻止读取 JSON 数据。

## 安装、启动与模型替换

不需要安装前端依赖。从仓库根目录启动配套服务：

```powershell
python projects/001-infinite-bookshelf/experiments/server.py
```

打开 [本地演示](http://127.0.0.1:8765/)。启动、模型配置和接口合同见 [实验说明](../experiments/README.md)。本地服务仅提供 `web/` 内的静态文件；浏览器中的配置说明不会链接到服务未公开的实验源码文件。

当前对话中的 GPT 可以直接生成保存后的样稿；网页持续自动生成新主题仍需独立的模型 API 配置。密钥只由本地服务读取，不输入网页、不保存到浏览器。

配套服务采用 OpenAI 兼容的 Chat Completions 协议。界面通过相对路径调用：

```text
GET api/config
POST api/generate
```

`api/generate` 返回 NDJSON 阶段事件；每一节完成后出现这节正文，并非逐 token 的文本流。页面停止等待使用 `AbortController`，可以终止前端接收；已经发送的模型请求仍可能在服务端执行。

## 纯静态预览与部署前缀

如果只希望阅读样稿，可从仓库根目录启动任意静态服务，例如：

```powershell
python -m http.server 8766 --directory projects/001-infinite-bookshelf/web --bind 127.0.0.1
```

打开 <http://127.0.0.1:8766/>。此时 `api/config` 不存在，网页会明确显示静态演示状态，模型 API 按钮不能启动生成；完整阅读、回放、导航、下载和打印仍可用。

无需构建；构建命令为「无」，输出目录就是本 `web/` 目录。未来汇集到 `site-dist/001-infinite-bookshelf/` 时，应完整复制 `index.html`、`styles.css`、`app.js`、`data/` 和 `assets/`。

预期访问前缀为 `/1013_codex_project/001-infinite-bookshelf/`，资源和 API 请求均相对当前页面解析，兼容这个子路径。页面没有客户端路由，刷新入口不会产生深层路由问题。GitHub Pages 只支持样稿模式，本地模型服务不会随静态页面发布。

**当前没有发布线上演示。** 未验证的地址不能填写到 `project.json.demo_url`。

## 验证范围

2026-10-13，先前页面的 `node --check app.js` 已通过。实际浏览器中已验证完整样稿、分步回放、停止与恢复、样稿切换及 MD / TXT 下载。通过临时本机伪服务验证了页面 → 后端 → 兼容接口 → 分节结果的完整路径，以及用量未报告、正文截断与文本安全渲染。测试服务不执行模型推理，验证后已关闭。证据见 [验证记录](../experiments/results/verification.md) 和 [项目 README](../README.md)；实际模型 API 仍未实测。

本轮扩展原理与理解说明后，已核查 HTML 标签闭合、54 个唯一 ID、全部页内锚点、现有 JavaScript 所需元素、静态资源与两份保存样稿。首页、摄影地址、CSS、JavaScript、摄影数据、健康与配置接口均返回 HTTP 200，首页响应与最新文件一致；JavaScript 语法、仓库索引及修改格式检查通过。原理说明在样稿工作台之前，正文约 7,000 字符。浏览器操作此前被安全策略拦截，本轮未通过其他自动化路径绕过；新版布局、交互和截图未重新进行浏览器验收。已有截图和上述交互测试属于先前页面。

本地 API 合同测试使用伪模型服务，不能视为真实模型生成。没有配置我们的模型 API 时，界面不会虚构模型请求次数、推理耗时或 token 消耗。
