# 原版提示词与执行顺序如何控制

**提示词决定“让模型写什么”，代码决定“何时调用、把哪份结果交给下一步”。** 本文按固定版本 `400b272175945d35eaefa68aefe9106fa9d7e467` 已读取的源码意译，研究日期为 2026-10-13；原版未完整运行，不把源码要求当作实际质量保证。

## 三个阶段各用什么提示词

| 阶段 | 固定模板的主要意思 | 插入的用户变量 | 输出 |
| --- | --- | --- | --- |
| 目录 | 写一份全面目录；省略前言、作者说明、总结等开头结尾内容；基础模式最多一层嵌套，标题与描述清楚、各节不重叠 | 主题、附加要求 | JSON 对象：标题对应描述，或对应下一层标题对象 |
| 书名 | 生成一个吸引人的书名，只写书名，不解释、不加装饰符号；系统模板要求 7–25 words（词） | 只有主题，不带目录与附加要求 | 一段书名文本 |
| 正文 | 以专业作者身份扩写本节，要求长、全面、有结构；认真遵守附加要求，只输出正文 | 本节标题＋描述、附加要求 | 流式正文，可含 Markdown |

依据：[目录模板](https://github.com/Bklieger/infinite-bookshelf/blob/400b272175945d35eaefa68aefe9106fa9d7e467/infinite_bookshelf/agents/structure_writer.py#L19)、[书名模板](https://github.com/Bklieger/infinite-bookshelf/blob/400b272175945d35eaefa68aefe9106fa9d7e467/infinite_bookshelf/agents/title_writer.py#L8)、[正文模板](https://github.com/Bklieger/infinite-bookshelf/blob/400b272175945d35eaefa68aefe9106fa9d7e467/infinite_bookshelf/agents/section_writer.py#L8)。

目录的“最多一层、不重复、不含前言”都是语义要求，代码不检查它们。书名的用户模板对 7 与 25 单词的表述本身有歧义，代码也没有词数校验；这个要求不能直接当作中文字符数标准。书名函数虽然接收 `model` 参数，请求时却写死 Maverick，忽略传入模型。

正文**没有完整目录、之前写过的正文或对话历史**。代码每次重新发送固定系统模板和本节变量。原始主题也未被直接传给正文函数，主题信息主要通过本节标题、描述和附加要求体现。同一个模型并不会因为前一次调用写过第一章，就自动记得它。

## 精确执行顺序

用户提交表单后，[基础入口](https://github.com/Bklieger/infinite-bookshelf/blob/400b272175945d35eaefa68aefe9106fa9d7e467/main.py#L80)按以下顺序运行：

1. **校验主题长度。** 少于 10 个字符就报错；通过后准备模型客户端。
2. **请求目录。** 等待模型完整返回目录字符串。
3. **请求书名。** 单独发主题，等待书名返回。
4. **解析目录。** 此时才调用 `json.loads()`，建立书稿对象并展示目录。即使目录最终无法解析，前面的书名请求也已经发生。
5. **递归逐节写。** 按模型返回的 JSON 键顺序遍历：值是字典就进入该分支，值是字符串就扩写该节。程序不按教学逻辑重新排序。逐个叶子节点执行，完成一节再进入下一节，没有并行生成。
6. **累加并显示。** 每个正文片段追加到对应小节，同时更新页面；流结束时累加推理统计。下载由另一个按钮触发，把已累积书稿汇总成文本或转换为 PDF，并非下一次模型调用。

正常情况下，有 N 个需扩写的小节，就有 N＋2 次模型请求。不存在自动审稿、重写或事实核查的后续调用。

## 哪些是程序强制，哪些只是要求

| 控制层 | 具体做法 | 实际边界 |
| --- | --- | --- |
| 内容要求 | 提示词要求全面、清晰、不重复、符合文风 | 模型尝试遵守；程序没有检查或修复质量 |
| 格式约束 | 目录请求用 JSON 模式，再用 `json.loads()` 解析 | 约束可解析格式；不验证章节设计、嵌套深度或事实 |
| 执行控制 | 函数调用顺序、递归、循环与流式追加 | 程序确定步骤及数据传递，模型不能自行换步骤 |
| 输出上限 | 目录和每节最多 8,000 tokens，书名最多 100 tokens | 只限制单次输出，不保证章节完整、字数或页数 |

目录和正文的 `temperature` 为 0.3，书名为 0.7，会影响生成变化程度，也不能保证每次结果一致。这里控制的是任务输入、结果格式和执行过程，不能控制模型内部如何思考，更不能保证内容正确。

也就是：**语义靠提示词，顺序靠代码，JSON 靠接口与解析，质量没有自动验收。**

## 高级模式增加了什么

[高级入口](https://github.com/Bklieger/infinite-bookshelf/blob/400b272175945d35eaefa68aefe9106fa9d7e467/pages/advanced.py#L84)把文风、难度、已有笔记和 UTF-8 TXT 内容直接拼进目录与正文提示词，还加上丰富例子、过渡自然、事实准确等要求。它没有检索或引用核验。目录改为“300 页以上长书”的要求，但没有计算页数或补写机制；书名仍只接收主题。

## 与本子项目演示的区别

摄影页面读取本次对话 GPT 已保存的参考稿，回放目录、书名和正文，**没有执行以上模型 API 请求**。我们的接口适配版另行加入完整目录，以及前面各节开头 600 字符的摘录；这些上下文不属于原版提示词，也不是模型摘要或全书审稿。真实 API 成稿质量尚未测量。
