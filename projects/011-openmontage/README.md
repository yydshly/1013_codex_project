## 能力、原理、价值与扩展摘要

<!-- BRIEF:START -->
**能力：** 覆盖主题研究、方案、脚本与分镜，图片/视频/配音和音乐素材，参考视频分析与真实镜头检索，已有视频裁剪、字幕、混音、调色、转码，以及程序化画面、时间线合成、预算、检查和导出。本研究归纳 34 项能力。

**原理：** 助手读取 YAML 中的阶段顺序、输入输出、允许工具和确认要求，再按 Markdown 技能完成工作；研究简报、脚本、分镜、素材清单和剪辑决策以 JSON 等文件交接，执行工具生成媒体，检查点记录进度并校验部分前置条件。

**核心价值：** 最值得复用的是阶段职责与结构化成果交接：把开放创作组织成可检查、可修改、可保存和可复用的过程，使工具选择有依据、返工有入口。其次是按能力替换执行工具和记录状态费用；实际省时、成本和质量优势尚未比较。

**可扩展场景：** 可探索知识库/RAG 资料到专题解说或课程视频、自有截图录屏素材库、中文发音与字幕规则、统一栏目模板、新生成模型和工具、实测质量评分、材料失效与外部任务恢复，以及多渠道交付。与写作、RAG 或 BaoCut 的衔接需适配格式、接口和验收，尚未集成。

## 回答我们之前讨论的几个问题

**它的本质是什么？** 可以称为视频制作 Agent 的技能、流程与工具系统。实际理解和调度由外部 AI 助手承担；OpenMontage 提供制作知识、阶段约定、成果格式、工具调用和状态记录。它没有在本次审查的架构里另起一个统一 Python 大模型调度器。

**主题、资料、参考视频都能作为输入吗？** 流程支持从主题或创意开始，也支持参考视频、既有长视频、播客、口播和录屏等入口。助手把不同输入整理成研究、方案、脚本和镜头需求；输入并非越少越好，时长、受众、素材来源与交付目标仍需确定。

**底层直接接模型，还是被模型当作 Skill 调用？** 两层都存在：外部助手读取 Markdown 技能与 YAML 流程，执行工作；生成工具再调用专门的图像、视频或语音服务，也有本地工具路径。技能文件本身不会生成视频，完整执行还需要依赖、素材和对应工具。

**只支持短剧吗？** 不是。固定目录有 12 条制作流程，覆盖讲解、动态图形、虚拟讲解员、角色动画、氛围片、长视频拆短、真实素材蒙太奇、混合制作、翻译配音、播客再利用、录屏演示与真人口播。角色动画不等于已经验证长篇短剧的角色、表演和跨镜头连续性。

**能生成代码来处理或绘制视频吗？** 助手可以调用处理工具、编写自定义脚本，以及使用 Remotion、HyperFrames 等描述画面与时间线。代码生成能力来自助手；本库提供约定、制作知识和执行接口。加工已有媒体与代码绘制画面是两种不同用途。

**最终还是模型理解，再调用工具处理、拼接视频？** 是。生成模型负责素材，本地渲染器负责媒体执行；脚本、分镜、选材、声音和剪辑决策决定最终内容。库的关键贡献是把这些判断放进可检查、可交接的过程。

## 最有价值的是什么

以下是结合本仓库研究用途的判断，尚未通过效率或费用实验比较。

1. **阶段职责与结构化成果交接。** 研究产出简报，方案约束脚本，脚本约束分镜，分镜约束素材，素材与剪辑决策约束渲染。成果可保存、检查、修改，减少反复从聊天记录解释需求。学习 Agent 工程时，这一设计比单纯收集更多生成接口更有复用价值。
2. **按能力组织不同执行工具。** 阶段请求配音、图像、运动画面或渲染能力，再根据当前可用性和约束选择工具。生成、检索和编程路线可以共享交接结构。替换提供商仍需适配参数、输出、错误、费用和任务控制，并非改一个名字就自动兼容。
3. **制作过程可观察。** 检查点、人工确认、费用记录、历史和交付检查，使失败或修改有明确入口。对较长或重复制作更有意义；简单剪切、转码也可直接使用媒体工具。

优点体现为有制作方法、有阶段成果、可复用模板、可回看花费、可定位返工位置。是否更便宜、更快、返工更少，仍需记录一次完整任务的实际成本、时间与人工修订。

## 它如何组合整套流程

### 三层分工

- **YAML：规定工作。** 每个阶段有 `skill`、`required_artifacts_in`、`produces`、`tools_available`、`review_focus`、`success_criteria` 与确认设置。
- **Markdown 技能：指导方法。** 指导助手如何研究、写脚本、设计镜头、选材、剪辑与复核。自然语言要求仍需要助手实际遵守。
- **JSON 成果与检查点：连接工作。** 成果保存内容，检查点记录阶段与状态，代码校验已知格式与部分阶段前置条件；下游从文件读取上游成果。

### 以讲解视频为例

| 阶段 | 输入和职责 | 主要产出 | 默认要求人工确认 |
| --- | --- | --- | --- |
| research | 主题、受众、目标；助手研究资料和角度 | `research_brief` | 否 |
| proposal | 简报、工具可用性；选择概念与制作路线 | `proposal_packet`、`decision_log` | 是 |
| script | 已选方案；旁白、时长与声音表达 | `script` | 是 |
| scene_plan | 脚本；镜头、时间、画面与素材要求 | `scene_plan` | 是 |
| assets | 分镜与脚本；生成、检索或编程制作素材 | `asset_manifest` 与实际素材 | 是 |
| edit | 分镜、素材；安排时间线、字幕、音乐 | `edit_decisions` | 否 |
| compose | 剪辑决策、素材；合成渲染并检查 | `render_report`、`final_review` 与成片 | 否 |
| publish | 渲染报告与检查结果；整理交付包 | `publish_log` 与导出目录 | 是 |

参考视频制作可在 proposal 增加 10–15 秒样片子阶段，并要求确认。这里的 publish 是导出阶段，不能据名称推断已经上传社交平台。

research、proposal、script、scene_plan、edit 等阶段的工具清单为空或主要依赖助手：这不是遗漏一个独立的研究模型服务，而是让当前助手用自身能力执行该职责。素材与合成阶段才连接相应执行工具。

### 代码校验与创作判断的边界

`lib/checkpoint.py` 会检查检查点 schema、阶段身份、标准阶段的必要成果、已知成果 schema，以及推进阶段时前序阶段的完成与确认字段。覆盖不等于 YAML 所有自然语言要求都自动验证：扩展阶段不一定有标准必要成果，未知成果类型不会按标准成果 schema 校验，未知流程也有兼容分支。

通过正常写入接口，默认有确认门的阶段不能直接记为完成而缺少 `human_approved=True`。该字段是调用者提供的记录，不能证明助手确实获得了人的确认。前序状态存在兼容历史数据的处理，不能当作不可绕过的安全边界。

写入会保存被替换的历史检查点并采用临时文件替换。`get_next_stage` 按流程顺序和完成状态定位下一步。这为继续制作提供依据；前置材料改动后的下游失效传播、外部生成任务恢复与全面一致性仍需另外处理，不等于自动恢复所有进行中的工作。

### 工具发现与选择

`tools/tool_registry.py` 发现 `BaseTool` 子类，汇总能力、提供商、可用状态及支持范围，并查询替代工具。选择器先按任务约束和工具可用性过滤候选，再评分。

| 评分维度 | 权重 |
| --- | --- |
| 任务适配 | 30% |
| 预期输出质量 | 20% |
| 控制能力 | 15% |
| 可靠性 | 15% |
| 成本效率 | 10% |
| 延迟 | 5% |
| 连续性 | 5% |

`lib/scoring.py` 支持工具提供质量、成功率和延迟等数据；缺少时使用稳定性标签、运行类型等默认值。任务适配涉及关键词和同义词重合，同一提供商也是连续性的经验信号。因此排名可解释，但不是经过统一实测的模型排行榜，也不保证人物或产品一致性。

### 费用与验收

费用路径为 estimate → reserve → reconcile，分别记录估算、预留和实际核算。默认预算模式为 warn：超可用预算记录警告；cap 抛出预算异常阻断预留。另有单次费用阈值、新付费工具首次使用确认；是否生效取决于实际调用链正确接入记录，并不是所有任意脚本自动受控。

合成前的 `delivery_promise`、`slideshow_risk` 检查部分镜头计划与画面要求。成片检查包含 ffprobe、四个位置（约 10%、35%、65%、90%）抽帧、音量检查，以及可选转录与脚本比较；部分字段只是粗略启发或文件存在性检查，缺少输入可能跳过，并非所有问题都阻断交付。它不能替代完整观看、试听、事实核查和审美验收。

Backlot 通过文件变化与 SSE 显示阶段、脚本、镜头、费用、事件和历史。上游说明为只读制作看板，确认通常发生在聊天；历史回放显示记录，不是重新调用模型生成。

## 三条制作路径

### 模型生成素材

脚本与分镜 → 图片／视频／TTS 等工具选择 → 请求模型或本地生成 → 保存和检查素材 → 剪辑决策 → 合成。素材模型决定单段能力，助手决定多段如何表达内容。成本包含生成重试，连续性与质量需逐次检查。

### 搜索真实镜头

资料与镜头描述 → 搜索与建库 → CLIP 相似度检索 → 镜头选择 → 剪辑与合成。候选来源包括 Archive.org、NASA、Wikimedia，以及可配置的素材站路径。

固定实现采用 `openai/clip-vit-base-patch32`，将图像与文字映射为归一化的 512 维向量；多帧均值表示视频片段。素材库保存片段、缩略图、`index.jsonl`、`embeddings.npy` 与 `tag_embeddings.npy`。检索融合画面与标签相似度（默认标签权重 0.3），并支持运动程度筛选及多样性选择。

相似度方便找画面，但均值表示弱化了时间顺序；画面匹配不能证明历史事件、地点、人物或事实。实际素材及许可需要核查原始来源。

### 用代码制作画面

内容与数据 → 布局、图形、动画和时间线代码 → 资源与参数检查 → Remotion／HyperFrames 等渲染 → 成片验收。适合项目原理、流程、动态图表、产品说明、分屏与画中画。已有视频也可通过 FFmpeg 等做切割、拼接、变速、字幕、混音和转码。

`video_compose` 根据 `render_runtime` 等路由至不同运行时。定制画面可保存并复用，但特殊布局并非都有现成预设；需处理字体、资源、时间、音轨和依赖。3D 工具目录存在 Blender、Three.js 与相关生成入口，本次只确认目录／示例，未逐项审查运行。

## 对当前研究仓库的价值

- **项目研究转视听内容。** 将已经核对的 README、架构图、截图和录屏整理为 60–90 秒项目解读，先说明用途，再解释核心原理和边界。
- **解释抽象系统。** 用程序化动画解释 RAG、远程终端、会话持续、网络隧道或 Agent 阶段交接，让时间关系与职责分工可见。
- **复用已有内容。** 将录屏、访谈、口播或长音频做字幕、混音、片段选择与再组织；无需每次生成全新镜头。
- **学习通用 Agent 组合方式。** 在其他研究、报告、实验任务中复用“职责 → 成果契约 → 工具 → 状态 → 验收”的思路。

与项目 001 长文写作、002 RAG 的衔接属于扩展设想：RAG 提供有来源的材料，写作步骤形成可靠解说，OpenMontage 组织视听制作。本仓库尚未连接为真实自动化系统。

## 新增理解：与已有研究项目的对比

比较依据是本仓库已有的固定版本研究和 2026-10-14 公开资料记录，不是相同任务的质量、速度或费用实测。OpenMontage 作为基准，另比较 10 个项目；Managed Agents 和 Vibe42 是公开产品资料研究，不能当作已审查完整源码的开源库。

模型理解、调用工具、保存成果是共同结构。关键差异是工作对象、谁组织执行、成果怎样交接、人怎样接手，以及代码具体检查哪些约定。

例如“将 RAG 研究制作成一分钟视频，再改第二段字幕”：OpenMontage 的参考重点是从资料到成片怎样逐阶段制作；BaoCut 的参考重点是人和 AI 怎样继续修改当前作品。两者能力有重叠，不能据此认定只会制作或只会编辑。视频、字幕和音轨的导入需适配，尚未验证项目直接互通；BaoCut 视频事务也不能直接套到独立设计画布上。

### 三个需要区分的环节

- **资料检索与镜头检索：** RAG 提供文本资料和回答依据；CLIP 路线寻找匹配画面。视觉相似不能证明事件、人物和事实。
- **助手模型与素材服务：** FCC 解决助手侧模型请求的协议与转发；OpenMontage 的图像、视频、TTS 提供商是各自的执行路径，需要分别适配。
- **工具评分与语义判断：** OpenMontage 七维评分包含权重和经验默认值；Jev 提供有限问题的语义判断，本地策略仍需约束、选择和验证。

### 对我们的组合价值

可以探索“RAG 提供资料与来源 → 形成可靠讲解 → OpenMontage 组织制作 → BaoCut 接续可编辑修改”。这是未来设计，不是已实现集成，需统一来源、素材、项目格式、模型、费用和验收。

Jev Skills 与 FCC 提供判断、路由和连接的参考；Managed Agents 提供任务编排和运行管理思路；cmux、Vibe42 提供现有会话工作台与远程入口。Jev SEO 与 REA 可借鉴检查、证据、版本和未知的记录方式，但领域规则和工具不能直接当作视频验收器。

网页完整对比见 [产品与项目对比](./web/index.html#comparison)，版本与来源清单见 [comparison.json](./web/comparison.json)。Jev SEO 行同时包含本仓库提取实验的理解，自有模型接入属于本仓库新增适配。

## 使用与扩展方向

### 建议的首个试点

选一个已研究清楚的项目，准备实际界面、原创原理图、核查资料和必要录屏。先用既有素材与程序化图解跑通短讲解，再测试生成镜头与复杂动画。先确定受众、时长、脚本和代表样片，最后完整观看与试听。

验收至少记录：脚本事实、字幕断句、术语发音、声音清晰度、画面与文案关系、来源许可、渲染成功、实际时长；比较助手／模型费用、重试次数、渲染耗时、人工修订和最终可用程度。

| 方向 | 扩展内容 | 价值与条件 |

| 内容输入 | RAG、论文、现有研究文档和引用记录 | 减少重复整理；保留资料与讲解结论的对应关系 |
| 栏目模板 | 统一片头、原理动画、对比卡与结尾 | 重复制作价值较高；模板仍需适配素材与时长 |
| 自有素材库 | 真实截图、录屏、原创图形和来源索引 | 提高可控性与复用，需更新索引与来源记录 |
| 新模型／工具 | 能力接口、参数、成本、错误与状态适配 | 扩大执行范围，先确认控制能力与可用环境 |
| 实测选择评分 | 质量、延迟、成功率、重试和费用日志 | 从默认经验转向自身任务数据，需统一评价条件 |
| 流程可靠性 | 材料依赖、下游失效、外部任务恢复、重试与人工入口 | 长任务更可控，需明确状态与操作语义 |
| 平台交付 | 各渠道的尺寸、字幕、封面与发布适配 | 现有导出包是起点，真实上传需要另外接入 |

## 本仓库的实践与改动

新增中文研究网页、34 项能力目录、12 条流程说明、27 项固定来源、原创理解图、可下载导读，以及用于解释阶段交接的交互。网页的模拟完成与模拟确认仅修改浏览器内存中的教学状态，不执行上游工具、不请求模型、不产生视频。

`research.json` 保存原创归纳，生成器将目录渲染到 HTML 和本文，并生成纯文字导读。教学 JSON 片段明确标注为简化示意，不冒充满足上游 schema 的完整生产成果。

没有复制上游完整代码、技能正文或素材；来源使用固定链接。上游、模型和第三方素材的许可分别按其来源核对。本次原创说明、样式、脚本和图示遵循本研究仓库约定。
