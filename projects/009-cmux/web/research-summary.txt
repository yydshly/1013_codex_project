cmux：一个人控制多个 Agent 的工作台与实现原理
研究日期：2026-10-14
上游：https://github.com/manaflow-ai/cmux
基准：cdbe99596fe13784ec5ea24d2e1c720a8f67f5cb

本质：把多个现有 Agent 会话放进一个工作台，分屏展示、独立交互、定向控制，让它们并行工作，实现一个人同时管理和控制多个 Agent 的能力。各 Agent 仍用自己的模型、工具和上下文。

能力：真实终端、多窗口 / 工作区 / 分屏，Hooks 与 OSC 通知、CLI / Socket、WebKit 自动化、Agent 收件箱、Claude teams 适配、事件规则、会话恢复与 SSH。

架构：Swift、AppKit、SwiftUI 管理宿主；libghostty 经 PTY 双向连接 Shell / Agent；WebKit 承载网页。Workspace / Surface / 生命周期标识与原生 session ID 贯穿定位、状态、控制和恢复。

原理：输入输出走 PTY，状态由 Hook / OSC / CLI 上报，操作经 Unix Socket 请求路由，消息先存储再由接收方 Hook 交付。模型与工具由 Agent 执行。

多 Agent：会话并行、独立上下文、定向提示和回复。人的终端输入与队友消息是不同路径。Claude 可空闲唤醒，Codex 空闲等待下一提示；等人回答时暂缓消息。read 不是任务验收。

分派：上层决定谁做什么，工作台送达与承载。Claude teams 的 tmux 操作映射为原生分屏；通用 fan-out 聚合在本研究版本的 RFC 中仍是 proposed。

场景：多项目研究、实现与浏览器检查、远程长任务和自有 Agent 流程。

对我的价值：一个任务执行时可以安排其他独立任务，减少找窗口、等待、漏看和材料搬运，将人的注意力用于分派、回应与验收。学习模型无关承载、稳定身份、状态、控制与消息的分层。当前 Windows 先参考架构；原生桌面端需要 Mac。实际效率与费用收益须对比同类任务。

扩展：任务契约与依赖、模型路由、适配能力声明、材料与产物、worktree / 合并、交付检查、费用记录与 Windows 宿主。已有事件和规则可用；终端兼容、会话代际、消息可靠性、恢复与权限仍有工程工作。

实现思路：复用已有 Agent 和模型，先承接进程、输入输出与稳定会话身份，再关联展示、状态、提醒、控制和消息，最后在上层补任务、依赖、隔离、失败处理与验收，逐步形成可复用工作流。

边界：Workspace 不等于文件隔离，状态不等于质量，终端输出不等于全部模型内部推理，应用恢复不保存所有进程内存。上游客户端、真实 Agent / 模型、恢复、云移动链路未实测；效率与费用收益未证明。

许可证：主体 GPL-3.0-or-later；指定 server 目录 BUSL-1.1，生产使用按上游声明需要商业许可；第三方按自身许可。
