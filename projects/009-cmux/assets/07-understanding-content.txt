02
底层原理：四条通道，共用 Surface / 生命周期 / 原生 session ID
输入 / 输出
UI ↔ PTY ↔ Shell / Agent CLI
ANSI 解析与渲染；OSC 可承载通知。模型调用在 Agent 侧。
状态 / 提醒
Hooks / OSC / CLI → 状态 / 通知存储
侧栏、通知环、未读与会话状态；丰富程度依赖具体适配。
程序化控制
人 / 脚本 / Agent → CLI / Unix Socket
显式定位 Workspace / Surface，创建、选择、输入、读取和操作浏览器。
协作消息
发送者 → queued → 接收方 Hook → delivered
消息加入上下文；投递轮结束或手动标记为 read，不修改人的草稿。
03
能力清单
终端与分屏：真实 CLI，多窗口 / 工作区 / 页签
状态与通知：运行、空闲、需输入，集中提醒
控制接口：创建、选择、文本、按键与屏幕读取
浏览器自动化：导航、快照、点击、填表、截图
Agent 消息：定向发送、收件箱、回复与投递状态
团队适配：Claude teams 的 tmux 操作映射为原生分屏
事件与规则：订阅、留痕、通知 / rpc / run / webhook
恢复与远程：布局、支持的会话恢复、SSH / tmux
04
接入方式：由基础到增强
1 终端接入：在 cmux 中启动已安装的 Agent CLI。
Agent 自己登录、配置模型、使用自己的工具。
2 状态接入：支持的 Agent 配 Hooks。
也可用 OSC 或 cmux CLI 发通知、上报状态。
3 控制接入：CLI / Socket 显式选择目标。
环境带有 Workspace / Surface 标识，定向操作。
4 协作接入：启用消息适配或支持的团队集成。
按目标发送 / 回复，交付时机取决于接收方适配。
CLI 能运行，不代表所有增强能力都已支持。
Claude 可空闲唤醒；Codex 空闲消息等下一次提示；等待人回答时暂缓交付。
05
使用场景
多库研究：分开组织研究、实验、页面与检查，少找窗口、少漏提醒。
开发与验证：终端实现、浏览器检查和结果反馈在同一工作台衔接。
远程长任务：在线远程宿主持有进程，本地观察、输入和重连。
个人工作流：借鉴身份、事件、消息和控制，按真实痛点扩展。
06
对我的意义
人的价值：一个人组织更多独立任务，少找会话、少漏提醒、少搬运。
研究价值：模型无关承载、稳定身份、状态 / 控制 / 消息分层。
我现在用 Windows：即时价值偏架构参考；原生桌面端需要 Mac。
是否采用：比较并行负担、返工、通过率、端到端耗时与总费用。
07
可扩展：在已有基础上补齐任务闭环
任务契约与依赖 · 模型路由 · 通用适配 · 材料与产物 · worktree / 合并 · 交付检查 · 费用与 Windows 宿主
已有事件、规则与消息可作基础；通用 fan-out 聚合在研究版本中仍是提案。原型容易，可靠交付与恢复仍需工程。
08
关键边界：可控的环境，需要明确策略与独立验收
能操作多个 Agent，不等于自动决定谁做什么。
read / idle 不等于任务完成，更不等于成果合格。
Workspace 不等于文件隔离，修改代码另需合并策略。
恢复布局不保留任意进程内存；保活需另有宿主。
屏幕输出与状态上报，不等于完整模型内部推理。
更多 Agent 不保证更快、更便宜；收益须实际测量。
