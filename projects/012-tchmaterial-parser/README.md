## 一句话定位与三个角色

这个库是一个面向国家中小学智慧教育平台的桌面下载工具。本次关注不同版本的小学教材及配套资料的批量获取与自动整理。

| 角色 | 提供什么 | 资源存在哪里 |
| --- | --- | --- |
| 国家中小学智慧教育平台 | 教材、课程及教学资源的浏览与使用入口 | 平台使用的资源服务器和 CDN |
| tchMaterial-parser | 搜索与选择教材、解析页面、下载和整理文件的程序 | GitHub 仓库存放代码；项目声明不存储、托管、分发教材 |
| 你的本地资料库 | 由你选择并下载的文件，可供离线阅读和后续整理 | 你选择的电脑目录 |

[平台官网](https://basic.smartedu.cn/)是具体的教育资源网站；“智慧教育”在这里是平台名称的一部分。该工具尚未包含教材正文提取、OCR、正文检索、向量索引或 AI 问答，不是已实现的 RAG 系统。

平台背景参见[教育部建设与应用介绍](https://www.moe.gov.cn/fbh/live/2022/54251/sfcl/202203/t20220301_603272.html)。该历史介绍用于说明平台定位与多版本教材来源，不将当时资源数量视为当前库存。

## 下载源与底层原理

### 地址分工

| 地址 | 作用 |
| --- | --- |
| basic.smartedu.cn | 浏览教材、课程和资源页面的官方入口 |
| s-file-1.ykt.cbern.com.cn / s-file-2.ykt.cbern.com.cn | 代码用于获取目录、分类、版本索引、资源详情和关联信息 |
| r1-ndr-private.ykt.cbern.com.cn 等 | 常见实际文件服务器；代码支持 r1 / r2 / r3 节点，但也保留元信息里已有的完整地址 |
| 你选择的本地目录 | 保存已下载文件 |

这是固定源码中的主要地址分工，不意味着所有平台文件永远只使用这些域名。资源列表、数据结构、文件地址和认证方式均可能随平台变化。

### 六步流程

1. **选择或粘贴链接。** 教材列表勾选与输入框同步；多个页面链接可按行输入。
2. **识别页面与编号。** 从 URL 提取 contentId、resourceId、activityId 或 courseId，判断资源类型。
3. **请求 JSON 元信息。** 按类型选择平台详情接口，获取标题、标签、关联资源和 ti_items 文件项。
4. **选出实际文件。** 文档优先源文件；音频按播放器 href、href-clip 等规则选择可播放文件；展开课程包关联资源并去重。
5. **认证并下载。** 私有资源按当前 URL 生成 X-ND-AUTH 签名；分块写入临时文件，控制并发、请求间隔和部分错误重试。
6. **整理并保存。** 适用时检查传输大小，写入 PDF 书签，再将临时文件替换为正式文件；停止或失败清理本任务临时文件。

“解析”指解析资源页面链接和元信息，目的是找到文件，不等于理解教材正文。

### 认证和可靠性

当前设置窗口要求包含 access_token、mac_key、diff 的登录凭据 JSON。签名以 URL、请求方法、nonce 等组成原文，用 mac_key 做 HMAC-SHA256 并 Base64 编码。diff 用于调整 nonce 时间戳。凭据存在本地配置，用于请求平台；文件直链本身不保证匿名可访问。

下载部分限制为三条工作线程，并用请求间隔缓和集中请求；HTTP 400 会在同一地址等待并重新签名重试，401 / 403 不靠切换节点解决。临时文件在完成后才成为正式文件；大小检查依赖响应头，压缩传输或未知大小有不同处理。这些措施不等于完整的内容校验或断点续传。

## 比直接从官网获取方便在哪里

官网是正常使用入口。只找一两本教材、直接在线阅读或观看课程时，官网通常足够。该工具的收益主要随批量需求与整理需求增加；不提高教材内容质量，也没有经实测证明固定的速度或节省比例。

| 任务 | 直接用官网 | 工具的额外便利 |
| --- | --- | --- |
| 偶尔获取一两本 | 按官网提供的方式获取即可 | 首次安装与凭据配置可能抵消便利 |
| 整学期、多学科、多版本 | 使用各资源的页面与获取入口 | 集中勾选或粘贴页面链接，统一排队 |
| 教材加配套音频 | 分别查看资源关联内容 | 教材解析时尝试获取关联音频 |
| 统一归档 | 自己决定命名和目录 | 自动标题命名与学段 / 学科 / 版本分类 |
| 批次中部分失败 | 自己记录并补齐 | 错误集中显示，重试失败项 |
| 再次下载同一批 | 自己检查哪些已有 | 跳过目标位置已有同名文件 |
| 本地章节跳转 | 取决于下载 PDF 本身 | 适用时写入平台目录书签 |

工具不省去版本确认、文件抽查和资料使用判断。保持在线学习、不想维护本地文件时，也不必为了“收集”而下载。

## 使用场景与对你的价值

| 场景 | 建议做法 | 实际价值 |
| --- | --- | --- |
| 家长准备小学一学期资料 | 先核对学校用书，再按学科与学期选一批 | 统一获取和整理，便于离线阅读 |
| 学生英语听力 | 选择对应版本教材并核对配套音频 | 教材和听力集中保存 |
| 教师备课 | 粘贴受支持的课程或备课页面，查看关联文件 | 减少相关材料逐项获取操作 |
| 小学教材版本比较 | 同年级同学科选两种版本，记录来源和版次 | 为人工比较章节和组织方式提供资料；不自动分析差异 |
| 个人本地资料库 | 保存文件并登记来源、版本与日期 | 日后能找到资料并核对出处 |
| 工程学习 | 阅读固定版本的认证、任务和文件处理实现 | 理解一个实用小工具如何把重复操作组织起来 |

结合本研究仓库，最直接价值是不同版本小学资料的批量下载与自动整理。与项目 002 的 RAG 研究连接时，可成为资料入口：下载 → 来源登记 → 正文提取 / OCR → 切块 → 建索引 → 检索与引用问答。当前工具只完成前段；后续步骤、质量和适用授权均需另行设计验证。

如果不经常批量获取资料，对你的直接使用价值有限；仍可作为认证、有限并发、临时文件、命名与失败处理的源码案例。其他教育网站、农业资料和论文来源需要新的适配，不是把任意链接粘贴进来即可。

## 如何对应学校课本

只凭“五年级数学上册”这样的书名不能确定一致。逐项核对：

1. 学段、年级和学科。
2. 上下册或具体册次。
3. 出版社、版别或编写体系。
4. 修订年份、版次；记录印次时不要将重新印刷自动视为内容修订。
5. 封面与版权页；必要时结合 ISBN 核对，ISBN 也不应作为唯一判断。
6. 目录、重点章节与学校要求；有疑问时按学校或教师给出的用书信息选择。

本仓库网页中的清单只是人工核对提醒；勾选完成不代表系统已经识别教材一致性。平台课程可辅助学习，但学校授课顺序、进度、补充内容和作业仍由学校与教师安排。

## 实际使用路线

1. 到[官方平台](https://basic.smartedu.cn/)确认目标教材与版本。
2. 从[上游 Releases](https://github.com/happycola233/tchMaterial-parser/releases)选择适合系统的程序，或按[贡献者指南](https://github.com/happycola233/tchMaterial-parser/blob/244170e17bf8bc97401f65e04d261533d252572a/CONTRIBUTING.md)从源码安装。
3. 先用一两本进行试下载，选择保存目录及是否添加 PDF 书签。
4. 在程序中勾选教材，或粘贴受支持页面链接；部分资源需要按上游说明设置登录凭据。
5. 使用下载管理查看状态，完成后抽查 PDF、音频、目录、版本与失败项。
6. 再扩大到整批；对已有同名文件，核对版本后再决定是否重新获取。
7. 下载网页提供的空白 CSV，手动记录来源、版次、日期、保存路径和抽查结果。

上游源码运行示例（说明性步骤，本研究未执行上游安装或启动）：

    git clone https://github.com/happycola233/tchMaterial-parser.git
    cd tchMaterial-parser
    git checkout 244170e17bf8bc97401f65e04d261533d252572a
    python -m pip install .
    python ./src/main.py

依赖见上游 pyproject.toml：Python 3.10+、Tkinter 图形界面，以及 requests、pypdf、Pillow、sv-ttk 等。发布包与固定主分支可能不同，复现时分别记录。凭据是账号敏感信息，应只在本地工具设置，不放进研究文档、CSV 或本仓库网页。

## 可扩展方向

| 顺序 | 扩展 | 为什么先做 / 后做 |
| --- | --- | --- |
| 1 | 来源、资源 ID、版本、日期、校验值、原文件与书签文件登记 | 先保证资料可追溯，避免同名跳过被误认为自动更新；书签会改变文件，分别记录原始和加工文件 |
| 2 | 持久任务、断点续传、更新识别和目录缓存 | 降低反复下载与重启后的整理成本；保持授权和请求节制 |
| 3 | 启用并验证更多资源目录，分离下载逻辑与界面，增加命令行 | 让现有解析能力更容易使用和连接其他流程 |
| 4 | 正文提取、OCR、音频转写、章节搜索 | 从可阅读的文件走向可检索的内容 |
| 5 | 带教材版本与原文页码引用的 RAG、章节比较与备课辅助 | 在内容与检索质量通过验证后增加；自动生成内容仍需核对 |

以上是本仓库的扩展建议，不是已完成的上游功能。代码 MIT 许可不等于教材版权许可；上游要求下载资源用于个人学习与教学参考，不用于商业用途或二次分发。本仓库没有打包教材、收集登录凭据或发布下载后端。

### 扩展场景与需要补充的工作

| 未来需求 | 当前下载器提供的基础 | 另外需要实现与验证 |
| --- | --- | --- |
| 家庭 / 教师资料台账 | 同一批教材与关联文件保存到本地 | 来源、资源编号、修订版次、获取日期、校验值和抽查记录，方便长期追溯 |

| 章节检索与人工版本对照 | 取得对应 PDF 和有条件可用的目录信息 | 正文提取 / OCR、章节对齐、搜索和出处展示；不能只用章节名称判断教学质量 |
| 备课材料库 | 受支持页面中的关联教学文件 | 文档格式处理、教材章节关联、来源登记、关键词检索与教师人工筛选 |

这些扩展使文件更容易追溯、检索和复用，但并未由本次网页实现。应先用明确版本的小规模资料验证，再扩大范围；其他网站与其他资料类型需要单独适配来源、格式及访问权限。
